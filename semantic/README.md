# Semantic Catalog

Human-reviewable business definitions for the database exposed by the `semantic-sql` MCP server.

Agents: read these files **before** writing SQL. Prefer `approved` definitions and say when you rely on a `proposed` one. Write SQL in the dialect reported by the `list_tables` tool.

## Layout

| Path | Contents |
| --- | --- |
| `entities/<table>.md` | One file per entity: table, primary key, columns, relationships, open questions |
| `metrics.md` | Metric definitions with SQL expressions |
| `glossary.md` | Business terms and their meaning |
| `examples.md` | Example questions with SQL |

The catalog is generated by following [`prompts/generate-catalog.md`](../prompts/generate-catalog.md), then reviewed by a human in Git.

## Rules

- Always include the **physical** table and column names in backticks.
- Every definition has a `Status:` of `proposed` or `approved`.
- Everything generated starts as `proposed`. Only humans change it to `approved`.
- Keep descriptions concise. Record ambiguities under an **Open questions** heading.
- No credentials or connection details.

## Entity format

```markdown
# Order

- **Status:** proposed
- **Table:** `orders`
- **Primary key:** `id`

A purchase made by a customer.

## Columns

| Column | Description | Status |
| --- | --- | --- |
| `id` | Unique order identifier | proposed |

## Relationships

- `orders.customer_id` -> `customers.id` — each order belongs to a customer.

## Open questions

- Which values can `status` take?
```

## Metric format

````markdown
## Revenue

- **Status:** proposed
- **Definition:** Revenue from completed orders. Cancelled orders are excluded.

```sql
SUM(orders.total) -- WHERE orders.status = 'completed'
```
````

## Example format

````markdown
## What was revenue last month?

- **Status:** proposed

```sql
SELECT SUM(total) FROM orders WHERE status = 'completed' AND ...
```
````
